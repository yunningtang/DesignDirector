    Documentation

    What is DESIGN.md?

    A structured markdown file that captures a website's complete design system — colors, typography, spacing, components, and usage rules. Designed to be read by AI coding agents.

    Why does it exist?

    Most AI-generated UI looks generic — a sea of gray boxes with blue buttons — because the AI has no context about your brand. Giving it a DESIGN.md file changes that entirely.

    Tools like Cursor, Claude Code, Codex, and Windsurf will read it automatically and generate UI that matches your design system — not some random template.

    What's inside?

    A DESIGN.md file has seven sections, organized from atomic tokens to high-level guidelines:

    01
    Mood & Atmosphere
    The feeling — minimal, playful, technical, warm.
    02
    Color Palette
    Semantic CSS variables with role-based naming.
    03
    Typography
    Font families, weights, and type scale.
    04
    Spacing & Radii
    Base unit, scale, and border radius tokens.
    05
    Components
    Button, card, input specs — ready to reproduce.
    06
    Do's & Don'ts
    Negative constraints so AI doesn't over-design.
    07
    Ready-to-use AI prompts
    Copy-paste prompts for Cursor, Claude, or Codex that reference the tokens above.

    How do you use it?

    Step 1. Grab any site or create your own, then download the DESIGN.md file.

    Step 2. Drop it in your project root directory, alongside package.json.

    Step 3. Tell your AI agent to follow it:

    Please follow the design system defined in DESIGN.md. Use the CSS variables and spacing scale exactly as specified. Refer to the Do's & Don'ts when making styling decisions.

    That's it. The AI will reference the file every time it writes UI code, ensuring consistency across your entire codebase.

    Tokens vs. rules — why both?

    Most design-token tools stop at exporting raw values: #1a73e8, 16px, Inter. But an AI handed only values still doesn't know when or how to use them.

    DESIGN.md pairs every token with a semantic name (--accent-primary is for CTAs, not backgrounds) and a usage rule (don't use accent on body text). That's the difference between a style sheet and a design system.
